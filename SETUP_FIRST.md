# Calapan BPLO: local setup

The active application has a React/Vite frontend and a LavaLust PHP/MySQL API. The former users/products/student demo, old PHP dashboards, sample migrations and browser-only demo stores have been removed. The bundled LavaLust framework and its error views remain.

## 1. Database and private environment

Keep the current private `backend/.env` and `backend/ca.pem`. The backend reads `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USERNAME`, `DB_PASSWORD`, and `DB_SSL_CA`. Keep the existing Aiven values; do not replace them with examples or commit them.

For a new database only, import `backend/database/bplo_schema.sql` with Navicat. For an existing older BPLO database needing payment tables, run from `backend`:

```powershell
php scripts/setup_manual_payments.php
```

Create an administrator only if one does not exist:

```powershell
php scripts/create_bplo_admin.php
```

Use a private terminal for account details. This script asks for a new administrator; no demo login is built in.

## 2. Start the backend

```powershell
cd backend
php lava serve 8000
```

Use the actual port printed in your terminal. PHP needs PDO MySQL, cURL, fileinfo, OpenSSL and the installed Composer dependencies. Keep `vendor`; run `composer install` only when dependencies need installing.

## 3. Start the frontend

In another terminal:

```powershell
cd frontend
npm.cmd install
npm.cmd run dev
```

The local frontend `.env` uses `VITE_API_BASE_URL=http://localhost:8000`. This is the backend origin, without `/api/bplo`. The frontend normally opens at `http://localhost:4173`. Include its actual origin in backend `ALLOW_ORIGIN` if your port differs.

## 4. Notifications and payments

Application confirmations, status changes, inspections and fee assessments automatically attempt email and SMS using registered account contacts and enabled backend channels. Applicant notification checkboxes have been removed. SMTP or Brevo HTTPS handles email; TextBee handles SMS. See `MANUAL_PAYMENTS.md` for payment setup, proof verification and delivery results.

## 5. Checks and caching

From `frontend`:

```powershell
npm.cmd run check:structure
npm.cmd run test:ui
npm.cmd run test:reports
npm.cmd run test:cache
npm.cmd run build
```

From `backend`, `php tests/automatic_notifications_test.php` runs isolated payment and notification checks. `node tests/manual_payments_http_test.mjs` verifies actual uploads/downloads with a temporary database and fake messaging providers.

The service worker is generated by `npm.cmd run build`, covers all application workspaces and caches only public assets. It is disabled in `npm.cmd run dev` so edits remain visible. Test the built app with `npm.cmd run preview` and a configured API origin; `npm.cmd run test:cache-browser` checks caching using a temporary headless browser and mock API.

For Render deployment, follow `DEPLOY_RENDER_AIVEN.md`: backend and frontend are separate GitHub repositories and separate Render services. The backend uses `backend/Dockerfile`; the frontend uses a Static Site build. No `deploy` folder, `.github` workflow or Blueprint is needed.
